# Data Model: Marketing Website and Developer Documentation

Only the inquiry is stored at runtime. Everything else is build-time configuration
or content in the repository.

## Site configuration

`apps/website/site.config.ts`. Each value reads an environment variable at build
time and falls back to a placeholder. Full list: [contracts/site-config.md](contracts/site-config.md).

| Field | Rule |
| --- | --- |
| `productName`, `companyName` | Non-empty. The only place either name is written in `src/` (`literals` check) |
| `siteUrl`, `docsUrl`, `portalUrl`, `apiBaseUrl` | Absolute `https` URLs; placeholders use `example.com` |
| `brokerHost` | Hostname only, shown in hardware docs |
| `contactAddress` | Email address shown in the footer and in form fallbacks |

## Hosted release record

Two parts, kept apart so the production commit never appears in public
([research R4](research.md#r4-docs-follow-the-hosted-release)).

| Part | Where | Rule |
| --- | --- | --- |
| Hosted commit | `WEBSITE_HOSTED_REF`: Actions secret in CI; `.local/website/website.env` locally | Full 40-character SHA on `main`; must exist in the clone. Never printed, never written to `.sources/meta.json` or `dist` |
| `schema_version` | `apps/website/hosted-release.json` | `hosted-release.v1` ([schema](contracts/hosted-release.schema.json)) |
| `features.adapters`, `features.agent_access` | Same file | Booleans; `false` excludes the gated docs folders and claims |

The commit is updated after each hosted deploy. The switches change by pull request.
The `drafts` check lists drafts that the new commit contains.

## Changelog baseline

`apps/website/changelog-baseline.json`: `operations` (sorted `METHOD /path` strings
under `/integration/v1`) and `event_types` (sorted `IntegrationEventType` values), as
of the latest changelog entry. `check-site changelog` fails when the hosted
contract's lists differ, until a changelog entry is added and the baseline refreshed
with `--update`.

## Docs page

Front matter on hand-written pages ([contracts/content.md](contracts/content.md)).

| Field | Rule |
| --- | --- |
| `title`, `description` | Required (Starlight) |
| `draft` | `true` means unreleased; left out of production builds |
| Folder | `…/adapters/**` and `…/agents/**` are gated by the matching feature switch |

Generated user guide pages add `help_revision` (integer ≥ 1, from the guide's
`revision`) and `requires` (from `required_capabilities`), and are never committed.

## Claim

`apps/website/src/claims.yaml`, keyed by id.

| Field | Rule |
| --- | --- |
| `text` | The statement as shown |
| `source` | Where it comes from: a docs route, a measurement, a dated document |
| `reviewed_by`, `reviewed_on` | Who approved it, and when |
| `feature` | Optional `adapters` or `agent_access`; the claim renders only while that switch is on |

A `<Claim>` must have either `doc` (a built route) or `id` (an entry here).

## Redirect

`apps/website/src/redirects.ts`: `{ from: string, to: string }` pairs. `from` is a
current-site path. `to` must be a built route (`redirects` check). Written to
`dist/_redirects` as `301`.

## Inquiry

D1 table `inquiries`, owned by the website Worker.

| Column | Type | Rule |
| --- | --- | --- |
| `id` | text, primary key | UUID generated by the form; repeats are ignored (idempotent) |
| `type` | text | `demo`, `assessment` or `question` |
| `name` | text | 1–120 characters |
| `email` | text | Valid address, ≤ 254 characters |
| `company` | text | 1–160 characters |
| `role` | text | `hardware`, `product` or `business` |
| `message` | text | 1–5,000 characters |
| `source_page` | text | Site-relative path, ≤ 512 characters |
| `received_at` | text | ISO 8601, set by the Worker |
| `status` | text | `pending`, `delivered` or `failed` |
| `attempts` | integer | Delivery attempts so far |
| `next_attempt_at` | text | When the cron may retry; null once delivered or failed |
| `last_error` | text | Error class only, never message content |
| `delivered_at` | text | Set on delivery |

Index: `(status, next_attempt_at)` for the retry scan.

The client address is used only by the rate limiter and is never stored.

### States

```text
pending ──deliver ok──▶ delivered ──30 days──▶ purged
   │
   ├─deliver fails──▶ pending (attempts+1, next_attempt_at = backoff)
   │
   └─24 h after received_at, still undelivered──▶ failed ──90 days──▶ purged
```

Backoff: 5 minutes, 15 minutes, 1 hour, then hourly. The cron runs every 5 minutes
and handles at most 50 rows per run. A `failed` inquiry stays readable for the team
through the runbook's query until it is purged.
