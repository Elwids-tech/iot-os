# Data Model: Public API Contract

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-10-11

This feature stores no database data. Its "data" is a set of files in the repository
and two files produced during CI. Each is listed with its fields, the rules that check
it and who writes it.

## Overview

```text
Laravel routes + controllers ─┐
supplements/*.yaml ───────────┼─ contract:export ─▶ contracts/openapi/openapi.json (committed)
pending-schemas.json ─────────┘                            │
                                                           ├─ redocly bundle integration ─▶ SDK types, oasdiff, published reference
                                                           ├─ redocly bundle platform ────▶ client-library types, developer reference
                                                           └─ test-time response checks ──▶ contract-coverage.json ─▶ contract:coverage
breaking-exceptions.json ─▶ breaking-change gate (oasdiff, integration only)
```

## 1. Contract document — `contracts/openapi/openapi.json`

Generated by `php artisan contract:export`; never edited by hand (a hand edit fails
`contract:export --check`).

| Part | Content | Source |
| --- | --- | --- |
| `openapi` | `3.1.0` | Scramble |
| `info.version` | `1.MINOR.PATCH`, the integration API version (R10) | `supplements/info.yaml` |
| `servers` | `[{url: "/api"}]`, so paths read `/v1/...` and `/integration/v1/...` | Scramble config |
| `paths` | 247 operations: 18 integration, 229 `api/v1` | Routes, inferred |
| `webhooks.integrationEvent` | The signed webhook delivery (headers and `integration-event.v1` body) | Supplement |
| `components.securitySchemes` | `session` (cookie, with the anti-forgery header and the `/sanctum/csrf-cookie` bootstrap described), `applicationToken` (HTTP bearer) | `supplements/shared.yaml`; each operation's `security` from the operation transformer |
| `components.schemas` | Resources inferred by Scramble; shared envelopes and hand-written bodies from supplements; `$ref`s to `../location/v1/*.schema.json` and `../rules/v2/workflow.schema.json` | Both |
| `components.responses` | Shared errors: `Unauthenticated` (401), `CsrfExpired` (419), `Forbidden` (403), `NotFound` (404), `Conflict` (409), `ValidationFailed` (422), `TooManyRequests` (429 with `Retry-After`), `RuntimeUnavailable` (503), `RangeTimeout` (504) | Supplement |
| Operation `x-*` fields | Vocabulary in [contracts/openapi-extensions.md](contracts/openapi-extensions.md) | Transformer, supplements |

**Rules**:

- Every route under `api/v1/*` and `api/integration/v1/*` has exactly one operation per
  method other than HEAD, and no operation exists without a route (inventory test).
- Every operation has `x-audience`; integration operations have `x-abilities`.
- Every non-pending operation has a closed schema for each JSON response (R7 defines
  "open").
- Every user reference is an integer (lint rule `iot/user-reference-integer`).
- An integration response object allows additional properties unless it references a
  versioned schema from `contracts/` that says otherwise (`location-fix.v1` is closed;
  its own versioning governs it).

## 2. Supplement — `contracts/openapi/supplements/<domain>.yaml`

Hand-written. One or more files per domain (for example `integration.yaml` and
`integration-events.yaml`) plus `shared.yaml` (components) and `info.yaml`.
Format: [contracts/supplement.schema.json](contracts/supplement.schema.json).

| Field | Meaning |
| --- | --- |
| `components` | Schemas, responses, headers, examples to add (names must not collide with inferred ones) |
| `operations["METHOD /path"]` | Patch for one generated operation: `summary`, `description`, `responses` (per status, replaces the inferred response for that status), `x-*` fields |
| `webhooks` | Webhook definitions (integration only) |

**Rules**: a key must match a generated operation (otherwise the export fails, which
keeps supplements from inventing operations); a supplement may not remove a response
that the code produces; `$ref`s to `contracts/` use paths relative to
`contracts/openapi/`.

## 3. Pending-schema list — `contracts/openapi/pending-schemas.json`

Hand-edited (shrink only). Format:
[contracts/pending-schemas.schema.json](contracts/pending-schemas.schema.json).

| Field | Meaning |
| --- | --- |
| `operations[].operation` | `METHOD /path` as in the contract |
| `operations[].domain` | Owning domain (`Devices`, `Automation`, …), used to plan follow-up pull requests |

**Lifecycle**: 247 entries after PR 1 → 229 after PR 3 (integration leaves) → 185 after
PR 6 → 155 after PR 7 (the 74 have left). Each later domain pull request removes its
entries.

**Rules**: sorted, unique, every entry exists, never more entries than on the base
branch, no integration operation after PR 3, no listed operation with a closed
schema.

## 4. Breaking-change exception ledger — `contracts/openapi/breaking-exceptions.json`

Hand-written in the pull request that makes an intended breaking change to the
integration API. Format:
[contracts/breaking-exceptions.schema.json](contracts/breaking-exceptions.schema.json).

| Field | Meaning |
| --- | --- |
| `id` | Stable slug, e.g. `2026-11-correct-alert-episode-type` |
| `change` | The oasdiff single-line text of the change, e.g. `GET /integration/v1/organizations/{organization}/alerts changed the response property 'episode' type` |
| `reason` | Why the break is acceptable (for example "the contract described the field wrongly; the platform never sent a string") |
| `sdk_version` | The SDK version that ships it; must equal the pull request's SDK version and exceed the base branch's |
| `added_on` | Date |

**Rules**: entries are append-only history; only entries added in the current pull
request can excuse its changes; every added entry must match a change reported in that
pull request (no speculative exceptions).

## 5. Contract coverage record — `apps/api/storage/framework/testing/contract-coverage.json`

Written by the test suite, ignored by git, read by `contract:coverage`.

| Field | Meaning |
| --- | --- |
| `checked[]` | `{operation, status, test}` for every response checked |
| `skipped[]` | `{test, reason}` for tests marked `#[WithoutContractCheck]` |

**Rules**: see [contracts/ci-gate.md](contracts/ci-gate.md), gate G4.

## 6. Generated types — `packages/*/src/generated/contract.ts`

Written by `pnpm contract:types`; never edited by hand.

| File | Source bundle | Notable output |
| --- | --- | --- |
| `packages/integration-sdk/src/generated/contract.ts` | `integration` | `components`, root aliases, `CONTRACT_VERSION`, runtime array of known event types |
| `packages/api-client/src/generated/contract.ts` | `platform` | `components`, `paths`, root aliases |

**Rules**: header names the contract version and bundle SHA-256; regeneration produces
no difference in CI.

## 7. Drift log — `specs/001-openapi-contract/drift-log.md`

Written during PRs 2, 3, 6, 7 and 8 (and kept by later domain pull requests in their own
descriptions). One row per discrepancy:

| Field | Meaning |
| --- | --- |
| Operation | `METHOD /path` |
| Source | `docs`, `api-client type`, `sdk type`, `inference` |
| Discrepancy | What disagreed with real behaviour |
| Resolution | What was changed (contract, type, doc), or "platform bug filed" (FR-033) |
| Pull request | Where it was resolved |

| Generated types | §6 |
| Pending-schema list | §3 |
| Breaking-change exception | §4 |
| Drift report | Output of the gates in [contracts/ci-gate.md](contracts/ci-gate.md) |
| Drift log | §7 |
