# Contract: Kit Layout

> **Amended by [spec 027](../../027-firmware-starter-kits/contracts/starter-layout.md)
> (2026-11-03).** Kits are a credential-free starter plus separate connection settings. The
> archive layouts below are replaced by spec 027's starter layout. The type headers,
> identifier rules and size warnings in this file still apply, except that the node's
> device type moves from `config/iotos_settings.c` to `generated/iotos_types.c`.

Both kits are ZIP archives built with `PharData` in a private temporary directory that
is always removed, as today.

## Gateway kit

File name: `<gateway-edge-node-id>-gateway-kit.zip`.

```text
README.md                       quickstart: build, flash, what to edit, one kit per gateway
kit.json                        sdk_version, generated_at, gateway uuid, profile codes + revisions (no secrets)
config/iotos_settings.h         broker host/port, group, edge node, host id, client id/username, password, CA PEM
config/iotos_settings.c         defines iotos_kit_settings, including the node's device type
config/iotos_types.h            includes every device type header; declares iotos_kit_types[] and IOTOS_KIT_TYPE_COUNT
config/iotos_type_<code>.h      one per device type, plus iotos_type_gateway_health.h for the node
sdk/                            the SDK release: include/, src/, ports/, third_party/coreMQTT/ (R3), LICENSE, THIRD_PARTY.md, CHANGELOG.md, VERSION
examples/rt1050-evkb-ethernet/  board example (CMake/armgcc, MCUXSDK_ROOT)
examples/desktop-simulator/     desktop gateway simulator (CMake), --devices <type>=<count>
```

`config/` holds the only files with secrets. The README says to keep them out of version
control and that the CA verifies the broker and is not a client certificate.

### `iotos_settings.h` (generated)

```c
/* Generated by IoT OS for gateway "<name>" (<uuid>) on <ISO time>. Keep private. */
#define IOTOS_KIT_BROKER_HOST   "mqtt.example.test"
#define IOTOS_KIT_BROKER_PORT   8883
#define IOTOS_KIT_GROUP_ID      "<group>"
#define IOTOS_KIT_EDGE_NODE_ID  "<edge>"
#define IOTOS_KIT_HOST_ID       "<host>"
#define IOTOS_KIT_USERNAME      "edge-…"      /* also the MQTT client ID */
#define IOTOS_KIT_PASSWORD      "…"
#define IOTOS_KIT_CA_PEM        "-----BEGIN CERTIFICATE-----\n" … "-----END CERTIFICATE-----\n"
#define IOTOS_KIT_GATEWAY       1             /* 0 in a direct-device kit */
extern const iotos_settings iotos_kit_settings;  /* defined in iotos_settings.c, also generated */
```

`iotos_kit_types[]` lists the downstream device types only; the node's own type is
`iotos_kit_settings.node_type`. A direct-device kit has no downstream types, so
`IOTOS_KIT_TYPE_COUNT` is 0 and the array holds a single `NULL`, which keeps it valid C99.

String values are C-escaped, and the generator rejects control characters.

### `iotos_type_<code>.h` (generated)

```c
/* Profile "<name>" (<code>) revision <n>. Metric order is the alias order; do not edit. */
static const iotos_metric_def iotos_type_<code>_metrics[] = {
    { "flow_rate",    IOTOS_DOUBLE,  "L/min", false },
    { "total_volume", IOTOS_DOUBLE,  "L",     false },
    { "valve_open",   IOTOS_BOOLEAN, NULL,    true  },  /* accepts commands */
};
static const iotos_device_type iotos_type_<code> = {
    "<code>", <revision>, iotos_type_<code>_metrics, 3
};
```

Types follow research R20. `<code>` is the profile code made into a C identifier
(`[a-z0-9_]`); a collision gets a numeric suffix. The generator warns, in `kit.json` and
in the API response, when a type's DBIRTH at the default ID length would exceed 4 KiB
(the default `IOTOS_TX_BUFFER`).

## Direct-device kit

File name: `<device-code>-connection-kit.zip`.

Unchanged files: `device-config.json`, `ca.crt`, `quickstart.md`.

Added:
- `config/iotos_settings.h` and `config/iotos_settings.c`, with `IOTOS_KIT_GATEWAY 0`.
- `config/iotos_types.h`, with no downstream types.
- `config/iotos_type_<code>.h` for the device's profile. It is the node type, because a
  direct device publishes its profile's metrics as node metrics.
- `sdk/` and `examples/` as above. The examples read `IOTOS_KIT_GATEWAY`:
  - the desktop simulator generates values for the node's own metrics and refuses
    `--devices`;
  - the board example leaves out its RS-485 polling task.
