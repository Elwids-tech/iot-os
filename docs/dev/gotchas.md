# Gotchas

Things that have cost time before. Add to this list when something surprises you.

## Data and API contracts

- **Users have no UUID.** The `users` table has no `uuid` column. Every API
  endpoint identifies users by integer id (`acknowledged_by`, `recipient_ids`,
  `created_by`, alert `assignee`, admin and organization member routes), so new
  user references in API contracts use `user_id`. See
  [ADR-013](../adr/ADR-013-integer-user-ids.md).
- **PHPUnit runs on SQLite.** [`apps/api/phpunit.xml`](../../apps/api/phpunit.xml)
  forces an in-memory SQLite database. SQLite never raises Postgres's `22P02`
  invalid-UUID error, so a malformed id that would be a 500 on Postgres passes in
  tests. Assert on the query log, or test against Postgres, when UUID parsing
  matters.
- **Laravel rewrites JSON request bodies.** The default global `TrimStrings` and
  `ConvertEmptyStringsToNull` middleware also clean JSON, so a posted `unit: ""`
  arrives as `null` and `"Alarm "` as `"Alarm"`, in `$request->validate()` and
  `$request->json()` alike. When a payload must round-trip byte for byte (the
  automation assistant stores the editor's draft and the portal compares it with
  its own), validate `json_decode($request->getContent(), true)` instead.
- **Never edit `contracts/openapi/openapi.json` by hand.** It is generated by
  `cd apps/api && php artisan contract:export`; CI's `contract:export --check` fails on
  any byte that a fresh export would not write. Change the code or a supplement in
  `contracts/openapi/supplements/` and export again
  ([API surface](../reference/api.md#contract)).
- **Generator pins change the contract.** `dedoc/scramble` is pinned exactly because a
  new version infers differently and rewrites `openapi.json`. Upgrade it in a pull
  request of its own that contains only the upgrade and the re-export.
- **The export migrates its own database.** Scramble reads column types from the
  schema, so `contract:export` migrates a temporary SQLite database in a child process
  and never touches yours. It refuses to run with cached configuration
  (`php artisan config:clear`). Run one export per process: a second export in the same
  PHP process can lose parameters Scramble inferred from method calls.
- **A new operation's response must be fully typed.** `contract:check` refuses open
  schemas on operations that are not in `pending-schemas.json`, and Scramble types
  `$collection->map(fn ($x) => [...])->values()` in a resource as `string` or `{}`. Move
  the mapping into a private method with a `@return list<array{...}>` docblock and cast
  `getKey()` (`(int)`), as `PlatformUserResource` does. Statuses from `abort_unless` are
  not inferred; add them to the domain's supplement.
- **PostgreSQL and SQLite serialise some values differently** (decimals, JSON key
  order, booleans read back from raw queries). CI runs the suite on PostgreSQL and is
  authoritative; describe what PostgreSQL returns in the contract, and check a
  surprising local result against PostgreSQL before changing a schema.
- **Extended Python validators stop at a `$ref` into another file.** jsonschema
  picks the validator class from a referenced document's `$schema`, so a
  `validators.extend` subclass (the contract checker's tolerant and secret modes)
  silently becomes plain `Draft202012Validator` inside every other contract. The
  checker validates copies of the schemas without `$schema`; do the same in any new
  Python tooling that extends a validator.
- **opis/json-schema is not standard by default.** Its plain `Validator` enables
  opis extensions: `default` fills in data, so `required` silently skips any property
  that has a default, and a `$ref` containing `{...}` is a URI template. Validate
  contract data with `CompliantValidator` (as the API response checks in
  `apps/api/tests/Support/Contract` do), and percent-encode `{` and `}` in JSON
  pointers into OpenAPI paths.
- **The runtime re-encodes device definitions.** `devices.Definition` and
  `devices.Mapping` use `omitempty`, so a definition the runtime sends on (the
  internal telemetry message) drops a null `ingress_conversion`, and Go reads an
  absent `conversion_mode` as `profile`. Write a contract for what each producer
  actually sends: configuration v2 makes both mapping fields optional for this
  reason, and the GPS demo seeder's configurations omit both.
- **`last_seen_at` means a packet arrived from the device.** The portal's freshness,
  the agents' `last_reading` check and `find_devices` all read it. A presence change
  that comes from the runtime's broker connection (restart, deploy, broker outage)
  must not set it: the runtime omits `last_seen_at` from that `device.presence.v1`,
  and `RuntimeController` keeps the stored value. Until 2026-10 it sent the current
  time, so every device on a connection looked freshly seen after each deploy.

- **`User` holds Passport tokens, not Sanctum's.** Passport and Sanctum both define a
  `HasApiTokens` trait with incompatible signatures, so a model can use only one,
  even through a subclass. People hold agent tokens (Passport). Portal sessions and
  integration application tokens still go through Sanctum. In tests, sign people in
  with `actingAs()`, because `$user->createToken()` now needs a Passport
  personal-access client.
- **Every auth guard gets seeded permissions.** `PermissionSeeder` creates each
  permission for every guard in `config('auth.guards')`, including Sanctum's runtime
  `sanctum` guard. A new guard that carries no roles must be excluded there, as the
  agent guard `mcp` is.
- **`withToken()` sticks for the rest of a test.** It sets a default header, so a later
  request made with `actingAs()` still sends the old bearer token. Call
  `withoutToken()` when switching from a token to a session within one test.
- **Laravel AI sends provider options verbatim.** An agent's `providerOptions()` is
  merged into the request body of whichever provider runs it, so OpenAI's `store`,
  `reasoning` or `parallel_tool_calls` make an Anthropic request fail. Return each
  provider's own options through `AssistantProvider::options()` (spec 010).

## Local stack

- **Containers build from source with no bind mounts.** A source edit does
  nothing to the served app until you rebuild the affected service
  ([local setup](local-setup.md#rebuild-one-service)).
- **A git worktree can be served the same way.** Run compose from the worktree
  with the main checkout's env files:
  `docker compose --env-file <main>/.env --env-file <main>/.local/devices/devices.env -f deploy/compose/compose.dev.yml -f deploy/compose/compose.app.yml -f deploy/compose/compose.devices.yml up -d --build --no-deps api alerts-worker webhooks-worker assistant-worker automation-worker portal admin`.
- **Check which files the running stack was started with before rebuilding.**
  The stack may have been started from another worktree, or with extra overlays
  (monitoring, adapters) and env files that no longer exist. Read the labels:
  `docker inspect <container> --format '{{index .Config.Labels "com.docker.compose.project.config_files"}}'`
  (and `com.docker.compose.project.environment_file`). Rebuilding the API family
  without the adapter env file breaks API to adapter-manager authentication
  (`IOT_ADAPTER_MANAGER_TOKEN` and `IOT_ADAPTER_HOST_STATE_DIR` are required).
  `compose.adapters.yml` does not define `portal` or `admin`, so a
  frontend-only rebuild does not need it.
- **Infrastructure config is bind-mounted from where compose ran.** NATS and Mosquitto
  mount `deploy/compose/*.conf` from that checkout. If it was a worktree that is
  later removed, Docker mounts an empty directory instead, and the service fails on
  its next restart: NATS exits 127 and the runtime loops on `lookup nats`. Start
  `nats` and `mqtt` from the main checkout.
- **A new or reset broker volume has no device credentials.** Mosquitto keeps them
  in `mosquitto-data`; until they are reapplied every login fails and the runtime
  logs `MQTT connection pending`. `./taskw devices:up` runs
  `php artisan devices:reprovision-broker`; run it in the `api` container after
  recreating the volume by hand.
- **Rebuilding `api` signs everyone out.** The dev API uses the `file` session
  driver inside the container ([`compose.app.yml`](../../deploy/compose/compose.app.yml)).
  This is expected, not a regression.
- **The dev stack does not serve the API the way a release does.** Releases put
  nginx ([`nginx.release.conf`](../../deploy/docker/api/nginx.release.conf)) in
  front of PHP-FPM. Its dotfile rule (`location ~ /\.`) once returned 403 for
  `/.well-known/oauth-*`, so agents could not discover sign-in on the pilot,
  although every dev check passed. Paths the API must serve from a dot
  directory need their own `^~` location; `manage.py smoke` checks agent
  discovery when agents are on.
- **`docker run --env-file` reads each line literally.** Unlike Compose env
  files, it strips no quotes and cannot hold a multi-line value. After the
  Passport keys (PEM) entered the pilot environment, the checkpoint restore drill
  failed with "variable '-----END PRIVATE KEY-----' contains whitespaces". Pass a
  private environment with `-e NAME` from the client's environment instead
  (`docker_run_environment` in [`manage.py`](../../tooling/release/manage.py)).
- **systemd starts timers that fall in the same minute together.** Timers default
  to `AccuracySec=1min`, so the pilot's metrics, notification reconcile and daily
  backup timers fired in the same second and raced for `operation.lock`. When the
  lock failed at once instead of waiting, a third of metrics runs and several
  scheduled backups failed with "[Errno 11] Resource temporarily unavailable".
  `BackupOverdue` stayed quiet because deploy checkpoints kept the backup metric
  fresh. Anything that takes the lock from a timer passes `Deployment.lock` a wait.
- **A fresh worktree has no `apps/api/vendor` and no `.env`.** Clone the main
  checkout's vendor directory (`cp -Rc`, never a symlink: Composer resolves
  `__DIR__` through the link and autoloads the main checkout's `app/`), then
  `composer dump-autoload`. Without `.env`, tests fail with "No application
  encryption key"; run with a throwaway key:
  `APP_KEY="base64:$(openssl rand -base64 32)" php artisan test --compact`.
  The main checkout's vendor can lag its own `composer.lock`; if `package:discover`
  fails with a missing class (such as `Laravel\Passport\Passport`), run
  `composer install` in the worktree.

## Device adapters

- **Time decoder budgets in CPU time, from the start of the tenant's code.** QuickJS
  calls its interrupt handler about every 10,000 operations, counted across all the
  evals in a runtime. The first eval in a fresh runtime is checked as it starts, but
  after the worker's setup eval a trivial decoder runs without a single check, so a
  test that needs the handler must loop (20,000 iterations is enough). The 100 ms
  budget used to be wall time started before the context and script were built, so a
  busy CI runner spent it before a trivial decoder ran (`error: 'interrupted'`), and a
  1 MiB input always did.
  [`decoder-worker.cjs`](../../services/adapters/lib/decoder-worker.cjs) now measures
  `process.threadCpuUsage()` from just before the decoder's script.
- **QuickJS checks its interrupt handler only between bytecode operations.** A
  single built-in call runs to completion: `/^(a+)+$/` on 28 `a`s and a `b` was
  still running after 7.8 s of CPU, and short loops over `indexOf`, `sort` or
  `JSON.stringify` of large values ran for 0.3–4.7 s. The worker deadline in
  [`decoder.cjs`](../../services/adapters/lib/decoder.cjs) catches these. It reads
  the worker's CPU time with `worker.cpuUsage()` (Node 22.19+), which works while
  the worker is stuck in QuickJS. A 500 ms wall-clock deadline here still failed
  1 in 40 runs under load.
- **No decoder limit may count wall time.** At `--cpus=0.25` with four busy loops,
  workers took up to 4.2 s of wall time to post `ready` for at most 190 ms of their
  own CPU, so a 5 s startup limit failed about 1 run in 20. With twelve loops, a
  30 s wall-clock limit stopped the backtracking-regex test before its 500 ms CPU
  deadline in 6 of 8 runs, and a 1 MiB input took up to 67 s to decode for 0.5 s of
  setup CPU. `decode()` now stops a worker only when its CPU time stops advancing
  for 30 s, or when setup passes 5 s of CPU.
- **Reading a worker's CPU time costs the worker CPU.** The worker thread answers
  `worker.cpuUsage()` itself, so a worker blocked in `Atomics.wait` still gains
  0.03 ms per read, and up to 0.5 ms on a busy host. A stall check that counts any
  advance as progress never fires; `decode()` needs 1 ms between reads. Reads
  reject with `ERR_WORKER_NOT_RUNNING` until the worker's environment exists (over
  2 s with twelve busy loops) and after it exits, but they resolve while a
  `--require` preload blocks, before the worker is `online`.
- **Mocked time outruns a real worker.** Ticking `t.mock.timers` past a real
  worker's CPU checks fits 30 s into milliseconds, in which the worker cannot use
  1 ms of CPU, so a working worker looks stalled. The decoder tests either mock
  `Worker.prototype.cpuUsage` and let only microtasks run between ticks (the real
  worker's messages wait until the test yields to the event loop), or move the clock
  only after the worker reports on a `BroadcastChannel` that it has blocked. Mocked
  timers' `refresh()` does not re-arm a timeout in Node 22, so re-arm with
  `clearTimeout` and `setTimeout`.
- **Reproduce host-load flakes in a CPU-limited container.** macOS shares CPU too
  evenly to stall a worker for 100 ms. `docker run --cpus=1` with four
  `node -e 'for(;;){}'` loops next to `node --test` reproduced that CI failure in 5 of
  40 runs. At `--cpus=0.25`, the old wall-clock worker deadline failed every run.
  More busy loops inside the container add load; Docker builds or busy containers
  beside it barely do, because each container keeps its CPU quota. Never use a
  `docker build --no-cache` loop as load: each build leaves new layers, and 275
  builds filled the Mac's disk until the Docker Desktop VM failed with
  `input/output error`.

## Browser tests and screenshots

- **Playwright browser version.** If the headless shell pinned by
  `@playwright/test` is not installed but another build is, point
  `launchOptions.executablePath` at the installed one
  (`~/Library/Caches/ms-playwright/chromium_headless_shell-<build>/...`) in a
  scratch config instead of downloading.
- **`vite preview` listens on `localhost` (::1).** E2E against it needs
  `STUDIO_BASE_URL=http://localhost:<port>`, not `127.0.0.1`.
- **`e2e/studio.spec.ts` needs a live API** at `STUDIO_API_URL` (default
  `127.0.0.1:8013`, started by `tooling/test-profile-studio.mjs`). Against
  `vite preview` alone it fails with "Failed to fetch".
- **Full-page screenshots break dashboards.** Playwright `fullPage` screenshots
  make react-grid-layout re-measure and collapse panels in the capture. Grow the
  viewport height instead.
- **Axe contrast failures whose colours change between runs** are samples taken
  mid-transition, not token bugs. Wait for
  `document.getAnimations().length === 0` before running axe, as
  `devices.spec.ts` and `onboarding.spec.ts` do.
- **Clicks inside an unfolding collapsible can be lost silently.** Playwright
  scrolls the `overflow-hidden` content to bring the target into its clipped
  strip, then the growing height moves the target between mousedown and
  mouseup. Playwright checks only the first event's hit target, so it reports
  the click as done while `click` fires on a parent. Wait for
  `document.getAnimations().length === 0` before clicking.
- **`rtk npx` rewrites to an npm script.** `rtk npx vite build` becomes
  `npm run vite`. Use `rtk proxy npx vite …` and `rtk proxy npx playwright …`.

## UI

- **Toasts sit bottom-right and pause under the pointer.** A sticky bottom
  action bar needs `ref={keepToastsAbove}`, and a panel docked to the right edge
  needs `keepToastsLeftOf`, both from `@iot-os/ui/components/sonner`, or toasts
  will cover their buttons.
- **A Radix `Select` keeps its old label when its options change.** Changing the
  value and the item list in the same render (for example switching provider and
  model together) leaves the trigger showing the placeholder. Give the `Select` a
  `key` tied to the option list so it remounts.
