# Gotchas

Things that have cost time before. Add to this list when something surprises you.

## Data and API contracts

- **Users have no UUID.** The `users` table has no `uuid` column. Every API
  endpoint identifies users by integer id (`acknowledged_by`, `recipient_ids`,
  `created_by`, alert `assignee`, admin and organization member routes), so new
  user references in API contracts use `user_id`. See
  [ADR-013](../adr/ADR-013-integer-user-ids.md).
- **Eloquent timestamps keep whole seconds.** Laravel writes `Y-m-d H:i:s` on
  PostgreSQL too, so two writes in the same second tie. Comparing a "last read"
  time with a "last activity" time misses activity in the second someone read;
  support tickets count activity with sequence numbers instead
  ([support](../features/support.md#history)).
- **`create()` silently drops attributes outside `#[Fillable]`.** `User` does not
  list `email_verified_at`, so `User::query()->create([..., 'email_verified_at' => now()])`
  saves an unverified account without any error, and unverified members can never
  be chosen as alert recipients. Use `forceCreate` or `forceFill` for attributes
  that are deliberately not fillable. Seeders are unaffected: `db:seed` unguards
  models.
- **PHPUnit runs on SQLite.** [`apps/api/phpunit.xml`](../../apps/api/phpunit.xml)
  forces an in-memory SQLite database. SQLite never raises Postgres's `22P02`
  invalid-UUID error, so a malformed id that would be a 500 on Postgres passes in
  tests. Assert on the query log, or test against Postgres, when UUID parsing
  matters.
- **Creating an `Organization` creates a billing account.** Every organization
  belongs to exactly one billing account (spec 023), so the model's `creating` hook
  makes one named after it unless `billing_account_id` is set, and `created` opens
  its assignment. Tests that need organizations on one account use
  `Organization::factory()->forBillingAccount($account)`. Quiet saves
  (`saveQuietly`, `WithoutModelEvents` in `DatabaseSeeder`) skip the hook, so
  `OrganizationSeeder` sets the account and assignment itself.
- **On SQLite, changing a column rebuilds the table, and the rebuild clears
  set-null keys that point at it.** Inside a migration's transaction foreign keys stay
  on, so dropping the old table fires `ON DELETE SET NULL` in every child table.
  The billing accounts migration makes `organizations.billing_account_id` required
  before it creates `billing_account_assignments` for that reason. Production runs
  PostgreSQL, but `contract:export` and the local suite migrate SQLite.
- **`assertThrows` with a closure needs a `bool` back.** Laravel calls the closure
  with the exception and treats its return value as the verdict, so
  `fn (HttpException $e) => $this->assertSame(409, $e->getStatusCode())` fails with
  "exception … was not thrown" even when it was. Return the comparison instead:
  `fn (HttpException $e): bool => $e->getStatusCode() === 409`.
- **Laravel rewrites JSON request bodies.** The default global `TrimStrings` and
  `ConvertEmptyStringsToNull` middleware also clean JSON, so a posted `unit: ""`
  arrives as `null` and `"Alarm "` as `"Alarm"`, in `$request->validate()` and
  `$request->json()` alike. When a payload must round-trip byte for byte (the
  automation assistant stores the editor's draft and the portal compares it with
  its own), validate `json_decode($request->getContent(), true)` instead.
- **Laravel's notifications stub stores `data` as text.** `make:notifications-table`
  writes `$table->text('data')`, and PostgreSQL cannot run JSON path queries
  (`where('data->organization_uuid', …)`) on text. The bell's migration makes it
  `jsonb` ([spec 022](../../specs/022-alert-bell/plan.md)).
- **A notification with a preset id goes to one notifiable.** Laravel keeps an id set
  in the constructor for every notifiable, so `Notification::send($users, $one)` with
  `AlertTransitionNotification` (UUIDv7 id) collides on the primary key. Create one
  instance per person, as `AlertProjector` does.
- **Never edit `contracts/openapi/openapi.json` by hand.** It is generated by
  `cd apps/api && php artisan contract:export`; CI's `contract:export --check` fails on
  any byte that a fresh export would not write. Change the code or a supplement in
  `contracts/openapi/supplements/` and export again
  ([API surface](../reference/api.md#contract)). Data files can change it too: the
  target ids in `firmware/starters/targets.json` are the firmware-kit and starter request
  enums, so a new target needs an export, and `./taskw lint` does not catch it.
- **Generator pins change the contract.** `dedoc/scramble` is pinned exactly because a
  new version infers differently and rewrites `openapi.json`. Upgrade it in a pull
  request of its own that contains only the upgrade and the re-export.
- **The export migrates its own database.** Scramble reads column types from the
  schema, so `contract:export` migrates a temporary SQLite database in a child process
  and never touches yours. It refuses to run with cached configuration
  (`php artisan config:clear`). Run one export per process: a second export in the same
  PHP process can lose parameters Scramble inferred from method calls.
- **A new operation's response must be fully typed.** `contract:check` refuses open
  schemas on operations that are not in `pending-schemas.json`, and Scramble types
  `$collection->map(fn ($x) => [...])->values()` in a resource as `string` or `{}`. Move
  the mapping into a private method with a `@return list<array{...}>` docblock and cast
  `getKey()` (`(int)`), as `PlatformUserResource` does. Statuses from `abort_unless` are
  not inferred; add them to the domain's supplement.
- **PostgreSQL and SQLite serialise some values differently** (decimals, JSON key
  order, booleans read back from raw queries). CI runs the suite on PostgreSQL and is
  authoritative; describe what PostgreSQL returns in the contract, and check a
  surprising local result against PostgreSQL before changing a schema. `jsonb` stores
  object keys shortest first, so compare a decoded object with `assertEquals`, not
  `assertSame`, which also compares key order (spec 024's tests failed only in CI).
  To run tests on PostgreSQL locally, start a throwaway `timescale/timescaledb` container
  and pass `DB_CONNECTION=pgsql` with a database whose name ends in `_test`.
- **Extended Python validators stop at a `$ref` into another file.** jsonschema
  picks the validator class from a referenced document's `$schema`, so a
  `validators.extend` subclass (the contract checker's tolerant and secret modes)
  silently becomes plain `Draft202012Validator` inside every other contract. The
  checker validates copies of the schemas without `$schema`; do the same in any new
  Python tooling that extends a validator.
- **opis/json-schema is not standard by default.** Its plain `Validator` enables
  opis extensions: `default` fills in data, so `required` silently skips any property
  that has a default, and a `$ref` containing `{...}` is a URI template. Validate
  contract data with `CompliantValidator` (as the API response checks in
  `apps/api/tests/Support/Contract` do), and percent-encode `{` and `}` in JSON
  pointers into OpenAPI paths.
- **The runtime re-encodes device definitions.** `devices.Definition` and
  `devices.Mapping` use `omitempty`, so a definition the runtime sends on (the
  internal telemetry message) drops a null `ingress_conversion`, and Go reads an
  absent `conversion_mode` as `profile`. Write a contract for what each producer
  actually sends: configuration v2 makes both mapping fields optional for this
  reason, and the GPS demo seeder's configurations omit both.
- **`last_seen_at` means a packet arrived from the device.** The portal's freshness,
  the agents' `last_reading` check and `find_devices` all read it. A presence change
  that comes from the runtime's broker connection (restart, deploy, broker outage)
  must not set it: the runtime omits `last_seen_at` from that `device.presence.v1`,
  and `RuntimeController` keeps the stored value. Until 2026-10 it sent the current
  time, so every device on a connection looked freshly seen after each deploy.
- **A rejected Sparkplug packet is one edge node's problem.** `sparkplug.Engine.Accept`
  drops only that edge node's session (sequence gap, bad alias, metric or datatype)
  or one device's (data before its DBIRTH), so the runtime's `rejectedPresence`
  reports unknown for those sources alone, once per device rather than once per
  packet while the edge waits for its rebirth. `connection.presence.v1` makes every
  gateway and candidate on the connection unknown in Laravel; send it only when the
  broker connection is lost. Until 2026-10 every rejected packet sent it, so one edge
  needing a rebirth (after a runtime restart, say) blanked every device beside it.
- **Any NBIRTH wipes the edge node's device registries.** `sparkplug.Engine.Accept`
  starts a new session for every NBIRTH that is not an exact duplicate, so every DBIRTH
  must follow it again. The embedded SDK re-queues every device on each NBIRTH.
- **One `seq` counter per edge node.** NDATA, DBIRTH, DDATA and DDEATH share it, and a
  gap takes the node offline until it rebirths. Send everything for one node through a
  single serialised path (the SDK's lock).
- **DDATA before its DBIRTH makes the runtime ask the whole node to rebirth.** That is
  why the SDK's `iotos_commit` returns `IOTOS_PENDING_BIRTH` instead of sending.
- **The broker grants only literal filters.** A gateway may subscribe to
  `spBv1.0/<group>/NCMD/<edge>`, `…/DCMD/<edge>/+` and `spBv1.0/STATE/<host>`; a
  per-device DCMD subscription is refused (`BrokerProvisioner`).
- **Commands arrive by name and are confirmed by a later reading.** The runtime sends
  NCMD/DCMD with the metric name, no alias, and counts a command done only when a live
  reading of the mapped state shows the new value within 30 s. Firmware must publish
  the new state after applying a command.

- **`User` holds Passport tokens, not Sanctum's.** Passport and Sanctum both define a
  `HasApiTokens` trait with incompatible signatures, so a model can use only one,
  even through a subclass. People hold agent tokens (Passport). Portal sessions and
  integration application tokens still go through Sanctum. In tests, sign people in
  with `actingAs()`, because `$user->createToken()` now needs a Passport
  personal-access client.
- **Every auth guard gets seeded permissions.** `PermissionSeeder` creates each
  permission for every guard in `config('auth.guards')`, including Sanctum's runtime
  `sanctum` guard. A new guard that carries no roles must be excluded there, as the
  agent guard `mcp` is.
- **`withToken()` sticks for the rest of a test.** It sets a default header, so a later
  request made with `actingAs()` still sends the old bearer token. Call
  `withoutToken()` when switching from a token to a session within one test.
- **Laravel AI sends provider options verbatim.** An agent's `providerOptions()` is
  merged into the request body of whichever provider runs it, so OpenAI's `store`,
  `reasoning` or `parallel_tool_calls` make an Anthropic request fail. Return each
  provider's own options through `AssistantProvider::options()` (spec 010).
- **Audit events go through `ActivityLog::record()`** (spec 024, ADR-028), into
  `activity_log`; `device_audit_events` is gone. Query `event`, `subject_uuid`,
  `causer_id` and `properties` (not `action`, `resource_uuid`, `actor_id`, `details`).
  Pass the actor explicitly: the package would otherwise attribute a runtime callback
  or job to whoever is signed in, so the recorder never lets it guess. `causer_id` has
  no foreign key, so deleting a user keeps their events.
- **A free-form object in a response fails `contract:check` (G3)** as an open schema.
  The activity feed returns details as a list of `{key, value}` text pairs instead, and
  its 200 body is described by hand in `contracts/openapi/supplements/activity.yaml`
  because Scramble reads values taken from a DTO's array properties as strings.
- **A deployment's `status` is never `applied`.** `automation_deployments.status` is
  `pending`, `succeeded` or `failed`; `applied` belongs to the workflow's and the
  device's `deployment_status`. Many test fixtures still seed deployments with
  `'status' => 'applied'`, which a real one never has, so a query that filters on it
  passes its tests and finds nothing on a real database (the integration location
  bindings did until this was fixed). Seed `succeeded` in new tests.

## NATS JetStream

- **Updating a stream NATS recovered rewrites its creation time.** After a restart, a
  stream's file store remembers the server's start time, and any update (a larger
  byte limit, a compression change, an operator's `nats stream edit`) writes that
  into the stream's metadata. The next restart then reports it as the stream's
  `created`. Seen on NATS 2.14.5. Never use `created` to recognise a stream: the
  workflow checkpoint and the reference committed consumer bind to the
  `iot.stream_id` metadata the runtime sets, which survives updates and restarts.
  They used to bind to `created`, which paused workflow evaluation after a limit
  raise and a NATS restart.
- **A compression change applies only after NATS restarts.** The stream reports S2 at
  once, but blocks keep being written uncompressed until the server reopens the
  stream, and blocks written before stay as they are until they expire. This is
  why the runtime compresses new streams only.
- **Byte limits count uncompressed bytes.** `IOT_NATS_*_MAX_BYTES` and
  `IOT_NATS_STORE_MAX_BYTES` cap message bytes, not disk, so compression saves disk
  without letting a stream hold more messages.

## Local stack

- **Containers build from source with no bind mounts.** A source edit does
  nothing to the served app until you rebuild the affected service
  ([local setup](local-setup.md#rebuild-one-service)).
- **A git worktree can be served the same way.** Run compose from the worktree
  with the main checkout's env files:
  `docker compose --env-file <main>/.env --env-file <main>/.local/devices/devices.env -f deploy/compose/compose.dev.yml -f deploy/compose/compose.app.yml -f deploy/compose/compose.devices.yml up -d --build --no-deps api default-worker alerts-worker webhooks-worker assistant-worker automation-worker portal admin`.
- **A shell-exported key beats the env file.** Compose interpolation prefers the
  shell's variables over `--env-file`, so an `OPENAI_API_KEY` exported in your
  profile silently replaces the one in `.env` on rebuild. Compare env hashes first and
  run compose with `env -u OPENAI_API_KEY` when they differ.
- **Check which files the running stack was started with before rebuilding.**
  The stack may have been started from another worktree, or with extra overlays
  (monitoring, adapters) and env files that no longer exist. Read the labels:
  `docker inspect <container> --format '{{index .Config.Labels "com.docker.compose.project.config_files"}}'`
  (and `com.docker.compose.project.environment_file`). Rebuilding the API family
  without the adapter env file breaks API to adapter-manager authentication
  (`IOT_ADAPTER_MANAGER_TOKEN` and `IOT_ADAPTER_HOST_STATE_DIR` are required).
  `compose.adapters.yml` does not define `portal` or `admin`, so a
  frontend-only rebuild does not need it.
- **Your shell's environment beats the env files.** Compose fills `${VAR}` from the
  shell before `--env-file`, so an `OPENAI_API_KEY` exported by your shell profile
  replaces the stack's key on rebuild without any warning. Compare each value's
  hash in `docker compose ... config --format json` with the running container's
  env first, and run compose under `env -u OPENAI_API_KEY` (or whichever variable
  differs).
- **A new API-image worker needs each overlay's settings too.** `compose.app.yml`
  gives every worker the shared API environment, but `DEVICE_RUNTIME_URL` and
  `DEVICE_RUNTIME_TOKEN` come from `compose.devices.yml`, which lists the services
  that get them. The `default-worker` (bulk onboarding, spec 026) failed every item
  with "The device runtime is not configured." until it was added there. The
  release compose gives all workers the same environment, so only dev needs this.
- **Infrastructure config is bind-mounted from where compose ran.** NATS and Mosquitto
  mount `deploy/compose/*.conf` from that checkout. If it was a worktree that is
  later removed, Docker mounts an empty directory instead, and the service fails on
  its next restart: NATS exits 127 and the runtime loops on `lookup nats`. Start
  `nats` and `mqtt` from the main checkout.
- **A new or reset broker volume has no device credentials.** Mosquitto keeps them
  in `mosquitto-data`; until they are reapplied every login fails and the runtime
  logs `MQTT connection pending`. `./taskw devices:up` runs
  `php artisan devices:reprovision-broker`; run it in the `api` container after
  recreating the volume by hand.
- **A pinned image that leaves its registry breaks a fresh `up` for every service.**
  Compose pulls the stack's images in parallel and one failed pull aborts the
  rest, so nothing starts. On 2026-11-05 Docker Hub refused
  `minio/minio:RELEASE.2025-09-07T16-13-09Z` ("repository does not exist"), and
  a reset Docker could not start the dev stack although nothing used MinIO. Local
  image caches hide this until a Docker reset or a new machine. MinIO was removed
  from the dev stack; for another image, `docker compose ... pull
  --ignore-pull-failures` names the missing one, and `up -d` with the other
  services listed starts the rest. Pin an image that is still published.
- **Rebuilding `api` signs everyone out.** The dev API uses the `file` session
  driver inside the container ([`compose.app.yml`](../../deploy/compose/compose.app.yml)).
  This is expected, not a regression.
- **The dev stack does not serve the API the way a release does.** Releases put
  nginx ([`nginx.release.conf`](../../deploy/docker/api/nginx.release.conf)) in
  front of PHP-FPM. Its dotfile rule (`location ~ /\.`) once returned 403 for
  `/.well-known/oauth-*`, so agents could not discover sign-in on the pilot,
  although every dev check passed. Paths the API must serve from a dot
  directory need their own `^~` location; `manage.py smoke` checks agent
  discovery when agents are on.
- **One event per request could not keep up with a 500-device gateway.** Until
  [ADR-031](../adr/ADR-031-batched-runtime-events.md) the runtime handed births, presence
  and device outcomes to the API one at a time (`devices-control-inbox`,
  `MaxAckPending(1)`): 22 to 43 per second on the dev API (`php artisan serve`), while
  500 simulated devices reporting every 10 s send 50 to 75. The backlog grew to 14,850
  events and activations reached the API minutes late. Events now go in ordered batches.
  Check the backlog with `curl -s "http://nats:8222/jsz?consumers=true"` from inside
  `api`; a script polling hundreds of single devices still slows the dev API.
- **nats.go will not subscribe to a durable consumer whose window differs.** Subscribing
  with `nats.MaxAckPending(n)` to an existing durable created with another value fails
  ("configuration requests max ack pending to be …, but consumer's value is …"), so a
  runtime that changes a consumer's window must update the consumer first
  (`widenInbox` in [`inbox.go`](../../services/runtime/internal/app/inbox.go)), and an
  older runtime cannot start against the widened consumer until it is narrowed again
  ([ADR-031](../adr/ADR-031-batched-runtime-events.md#consequences)).
- **`docker run --env-file` reads each line literally.** Unlike Compose env
  files, it strips no quotes and cannot hold a multi-line value. After the
  Passport keys (PEM) entered the pilot environment, the checkpoint restore drill
  failed with "variable '-----END PRIVATE KEY-----' contains whitespaces". Pass a
  private environment with `-e NAME` from the client's environment instead
  (`docker_run_environment` in [`manage.py`](../../tooling/release/manage.py)).
- **systemd starts timers that fall in the same minute together.** Timers default
  to `AccuracySec=1min`, so the pilot's metrics, notification reconcile and daily
  backup timers fired in the same second and raced for `operation.lock`. When the
  lock failed at once instead of waiting, a third of metrics runs and several
  scheduled backups failed with "[Errno 11] Resource temporarily unavailable".
  `BackupOverdue` stayed quiet because deploy checkpoints kept the backup metric
  fresh. Anything that takes the lock from a timer passes `Deployment.lock` a wait.
- **A fresh worktree has no `apps/api/vendor` and no `.env`.** Clone the main
  checkout's vendor directory (`cp -Rc`, never a symlink: Composer resolves
  `__DIR__` through the link and autoloads the main checkout's `app/`), then
  `composer dump-autoload`. Without `.env`, tests fail with "No application
  encryption key"; run with a throwaway key:
  `APP_KEY="base64:$(openssl rand -base64 32)" php artisan test --compact`.
  The main checkout's vendor can lag its own `composer.lock`; if `package:discover`
  fails with a missing class (such as `Laravel\Passport\Passport`), run
  `composer install` in the worktree.
- **`docker rm -f` keeps a container's anonymous volumes.** An image that declares
  a `VOLUME` (PostgreSQL, TimescaleDB) gets a new anonymous volume per container,
  and only `docker rm -v` removes it. The pilot restore drill left 2-3 GB per run
  until it passed `-v`. Before removing dangling volumes on a server, check that
  each one is a drill leftover (`PG_VERSION` in a volume no container uses).
- **A deploy recreates services in parallel unless `depends_on` orders them.**
  `Deployment.deploy` recreates every application in one
  `up -d --force-recreate --no-deps`. Compose still orders the services named in
  that command by `depends_on`, but the runtime had none, so it started while
  `api-web` was being replaced. Its first control-plane call failed with
  `lookup api-web on 127.0.0.11:53: server misbehaving` and Docker restarted it
  twice on every pilot deploy. The runtime now waits up to two minutes for the
  control plane (`awaitControlPlane`), and the release `runtime` starts after
  `api-web`. A service that calls another one at startup needs both.
- **Two restarts can trip `ContainerFailure` despite its `> 2`.**
  `iot_container_restarts_total` is Docker's `RestartCount` for the service's
  current container, so a recreate resets it. From zero, two restarts read as
  exactly 2 in `increase(...[15m])`; after a reset from a non-zero count,
  Prometheus extrapolates them to 2.03 and the alert fires. So the restarts one
  deploy left behind made the next deploy's two restarts alert.
- **A release that adds a Caddy import crash-loops the old Caddy once.** `ship.py`
  installs the new source before the pre-upgrade checkpoint, and the checkpoint
  restarts the stopped containers it found running. The old Caddy container then
  reads the new `Caddyfile` through its bind mount but lacks the new file's mount,
  so `import /etc/caddy/webhooks.Caddyfile` fails ("File to import not found") and
  Docker restarts it until the deploy recreates it. On 2026-10-28 that was 7
  restarts in about three minutes, inside the deploy's own Caddy downtime, and
  `ContainerFailure caddy` fired for 15 minutes after a clean ship. Expect it the
  first time a release adds a mounted file; later releases already have the mount.
- **Services in a release overlay must also be started by `manage.py`.** `deploy`
  recreates an explicit list of services, not everything in the overlays, so
  `webhook-receiver` shipped in `compose.adapters.yml` but never ran. Adapter
  services now come from `ADAPTER_SERVICES`, and a test compares it with the
  overlay's services that have their own image.
- **Python's `tarfile` data filter leaves directory modes to the umask.**
  `extractall(..., filter="data")` ignores the modes an archive records for
  directories. The release tooling runs under umask 077, so from the 2026-10-10
  deploy on, every directory of the pilot's installed source was 0700 and owned by
  root (files kept 0644). Single-file mounts such as Loki's config and
  `mosquitto.conf` still worked, because only the mounted file's own mode counts.
  Grafana (uid 472) mounts its provisioning *directory*. It logged `can't read
  dashboard provisioning files ... permission denied` on every start and ran on
  what its database already held. [`ship.py`](../../tooling/release/ship.py) now
  sets 0755 and 0644 after unpacking. A directory mounted into a container that does
  not run as root must be readable by others (`find <dir> -type d ! -perm -0005`
  lists the ones that are not). A `source-before-…` tree kept from before the fix
  still has 0700 directories. Grafana also logs an error for a missing `alerting/`
  or `plugins/` provisioning directory, which fires `ServiceErrorLogs` too, so each
  holds an `apiVersion: 1` file.
- **A deliberate paho `disconnect()` ends the `loop_start()` thread.** A simulator
  that powers its box off with `disconnect()` and later calls `reconnect()` opens a
  socket nobody reads: no CONNACK, no `on_connect`, no birth. Call `loop_stop()`,
  then `connect_async()` and `loop_start()` again, outside any lock the callbacks
  take ([`fire_watch_box.py`](../../tooling/simulators/fire_watch_box.py)).

## Device adapters

- **Polled readings can be stale before the automation sees them.** A DAG binding's
  `fresh_seconds` counts from the reading's observed time
  ([`evaluator.go`](../../services/runtime/internal/dag/evaluator.go)), and a polling
  adapter publishes the vendor's observed time, which is up to one poll interval (plus
  the vendor's delay) before the reading arrives. With the old fixed 120 s and a
  five-minute poll, most readings were accepted and immediately `unknown: stale`, so a
  compare → alert chain never fired and the trace only said the source was stale. The
  editor now sizes freshness to at least two poll intervals (`poll_interval_seconds` on
  `GET workflows/dag/resources`) and warns below that; the automation assistant still
  defaults to 120 s.
- **Time decoder budgets in CPU time, from the start of the tenant's code.** QuickJS
  calls its interrupt handler about every 10,000 operations, counted across all the
  evals in a runtime. The first eval in a fresh runtime is checked as it starts, but
  after the worker's setup eval a trivial decoder runs without a single check, so a
  test that needs the handler must loop (20,000 iterations is enough). The 100 ms
  budget used to be wall time started before the context and script were built, so a
  busy CI runner spent it before a trivial decoder ran (`error: 'interrupted'`), and a
  1 MiB input always did.
  [`decoder-worker.cjs`](../../services/adapters/lib/decoder-worker.cjs) now measures
  `process.threadCpuUsage()` from just before the decoder's script.
- **QuickJS checks its interrupt handler only between bytecode operations.** A
  single built-in call runs to completion: `/^(a+)+$/` on 28 `a`s and a `b` was
  still running after 7.8 s of CPU, and short loops over `indexOf`, `sort` or
  `JSON.stringify` of large values ran for 0.3–4.7 s. The worker deadline in
  [`decoder.cjs`](../../services/adapters/lib/decoder.cjs) catches these. It reads
  the worker's CPU time with `worker.cpuUsage()` (Node 22.19+), which works while
  the worker is stuck in QuickJS. A 500 ms wall-clock deadline here still failed
  1 in 40 runs under load.
- **No decoder limit may count wall time.** At `--cpus=0.25` with four busy loops,
  workers took up to 4.2 s of wall time to post `ready` for at most 190 ms of their
  own CPU, so a 5 s startup limit failed about 1 run in 20. With twelve loops, a
  30 s wall-clock limit stopped the backtracking-regex test before its 500 ms CPU
  deadline in 6 of 8 runs, and a 1 MiB input took up to 67 s to decode for 0.5 s of
  setup CPU. `decode()` now stops a worker only when its CPU time stops advancing
  for 30 s, or when setup passes 5 s of CPU.
- **Reading a worker's CPU time costs the worker CPU.** The worker thread answers
  `worker.cpuUsage()` itself, so a worker blocked in `Atomics.wait` still gains
  0.03 ms per read, and up to 0.5 ms on a busy host. A stall check that counts any
  advance as progress never fires; `decode()` needs 1 ms between reads. Reads
  reject with `ERR_WORKER_NOT_RUNNING` until the worker's environment exists (over
  2 s with twelve busy loops) and after it exits, but they resolve while a
  `--require` preload blocks, before the worker is `online`.
- **Mocked time outruns a real worker.** Ticking `t.mock.timers` past a real
  worker's CPU checks fits 30 s into milliseconds, in which the worker cannot use
  1 ms of CPU, so a working worker looks stalled. The decoder tests either mock
  `Worker.prototype.cpuUsage` and let only microtasks run between ticks (the real
  worker's messages wait until the test yields to the event loop), or move the clock
  only after the worker reports on a `BroadcastChannel` that it has blocked. Mocked
  timers' `refresh()` does not re-arm a timeout in Node 22, so re-arm with
  `clearTimeout` and `setTimeout`.
- **Reproduce host-load flakes in a CPU-limited container.** macOS shares CPU too
  evenly to stall a worker for 100 ms. `docker run --cpus=1` with four
  `node -e 'for(;;){}'` loops next to `node --test` reproduced that CI failure in 5 of
  40 runs. At `--cpus=0.25`, the old wall-clock worker deadline failed every run.
  More busy loops inside the container add load; Docker builds or busy containers
  beside it barely do, because each container keeps its CPU quota. Never use a
  `docker build --no-cache` loop as load: each build leaves new layers, and 275
  builds filled the Mac's disk until the Docker Desktop VM failed with
  `input/output error`.

- **Re-provisioning a Mosquitto Dynamic Security client disconnects it.** The
  `disableClient` / `modifyClient` / `enableClient` sequence the manager uses kicks a
  connected client. The webhook receiver's identity was re-provisioned on every
  secret change, so the first delivery after each one was answered `503`.
  `manager.cjs` now provisions it only when the broker or password changes, and the
  receiver waits up to 3 s for a reconnect before refusing (spec 020).
- **MQTT 5 ends a session at disconnect unless it has an expiry.** With
  `protocolVersion: 5`, `clean: false` alone keeps nothing; the webhook source sets
  `sessionExpiryInterval` (7 days) so the tenant broker queues deliveries while the
  runtime restarts. mqtt.js reports PUBACK reason 16 (no matching subscribers) as a
  success; the receiver reads it from `packetreceive`.
- **mqtt.js acknowledges after `handleMessage`.** Overriding
  `client.handleMessage(packet, callback)` delays the PUBACK and the next packet until
  the callback, which is how adapter sources apply backpressure instead of dropping.
  Never call the callback of a client you have ended: a queued PUBACK can acknowledge
  the wrong message on the next connection.
- **Activating an adapter device sees a birth from the old flow.** The runtime hands
  on the source's live birth when the device's configuration activates, or asks the
  edge node to rebirth when it has none. Either birth comes from the flow still
  running, so its metrics carry no provenance: the binding arrives with the next
  deployment. The runtime now skips adapter readings with no provenance instead of
  storing them as invalid. Deduplication keys are recorded only for stored (bound)
  readings, so a cursor reset after activation backfills previews.
- **Assistant tools get verbose search queries.** Models pass sentences such as "GPS
  asset tracker location stream profile with fields lat lon" to search actions;
  `OnboardingTools::find` matches any word and ranks by matches. Give each tool's
  description the exact argument shapes, and keep results small: the per-reply
  budget (`IOT_ASSISTANT_RUN_BUDGET_USD`, 0.04 by default) is spent on context.
- **In a release, reach the API at `http://api-web`, never `api:8000`.** The dev
  stack's `api` serves HTTP on 8000; the release's `api` is php-fpm and `api-web`
  (nginx) serves it on port 80. The release adapter overlay had copied the dev URLs,
  so the webhook receiver's delivery reports and the tenant runtimes' deploy
  acknowledgements were refused, while deliveries still got `202`: no samples, and
  no adapter could finish deploying on the pilot. `test_release.py` now checks every
  release service URL that points at the API.
- **A null Node-RED credential crashes the tenant runtime.** `setFlows` reads each
  credential's `.length`, so a `null` throws an uncaught `TypeError` in
  `credentials.js` and the deployment is never confirmed. The release adapter worker
  still pointed `DEVICE_MQTT_CA_FILE` at a mounted `/certs/ca.crt` after the broker
  moved to a public certificate; Docker had created that host path as an empty
  directory, so the deploy job sent `ca_certificate: null`. The worker now uses the
  system bundle like the API.
- **Every adapter redeploy used to take all its sources offline.** The publisher kept
  its sources' births only in memory and sends NDEATH on close, so after a redeploy
  each source stayed offline until it reported again. Activating a device redeploys
  the adapter, so activating a second device before the others reported failed with
  "Source is offline or needs a fresh birth certificate" (minutes to an hour for
  cellular trackers). The same gap made a polling cursor reset rewind each active
  device's latest values: the first old record re-read after the redeploy went out
  as a fresh DBIRTH, and the runtime takes birth values as current. The publisher
  now keeps births in `births-<adapter>.json`. The first deploy after the runtime
  image changes can still time out while the old container's webhook source stops;
  deploying again succeeds.
- **One partial birth used to block a device's automations.** After a redeploy the
  publisher announced a source from its first record alone, and a polled record
  without one reading went out as a DBIRTH with 8 of the device's 9 mapped metrics.
  The full DBIRTH followed 16 ms later. The runtime set `review_required` on the
  first, and only a new device activation cleared it. Commands were refused, and an
  automation's activation failed with `binding_changed`, although its binding was
  exact. Three things changed. The runtime clears review on the next birth that
  matches the applied configuration
  ([ADR-025](../adr/ADR-025-review-follows-current-birth.md)). Automations report
  `device_review_required`. The publisher writes `births-<adapter>.json` before it
  announces a changed metric set, because the 30 s write interval let a crash
  restore a smaller set.
- **A refused device activation broke every automation bound to the device.** A
  device had one generation. Each activation request advanced it, refused or not, and
  bindings, telemetry and Laravel's checks all compared against it. On the pilot, a
  polled tracker's apply was refused as offline. The device moved from generation 1
  to 2 with the same configuration, and its automation failed `binding_changed` until
  it was saved again. Bindings now use the applied generation
  ([ADR-027](../adr/ADR-027-adapter-fed-activation-and-applied-generation.md)), and
  an adapter-fed source activates against its stored birth when it has no live one.
- **A release never updates tenant adapter runtimes.** `manage.py deploy` pulls
  Compose service images only. `ADAPTER_RUNTIME_IMAGE` is the image
  `adapter-manager` starts tenant runtimes from, so the release neither pulls it nor
  recreates them: it stops the tenant containers and starts the same ones again. Each
  tenant keeps its old runtime until its adapter is deployed again, by saving it or
  activating one of its devices. That deploy fails until the new image is on the
  host, because the manager compares image IDs with `docker image inspect`. On the
  pilot, a runtime without `births-<adapter>.json` outlived the release that added
  the file. After a platform deploy restarted it, it announced only its node, and
  polled trackers looked offline until their next reading. After a release that
  changes the runtime image, run `docker pull` with the release's
  `ADAPTER_RUNTIME_IMAGE` on the host, then redeploy each running adapter. The
  publisher announces every known source when it reconnects.
- **A backfill could leave a new source in Discovery as `src-<hash>`.** The Reporter
  drops reports while four are in flight, and the preview report is what tells
  Laravel the vendor's serial for a Sparkplug source. A tracker with one record in a
  large backfill lost its only preview. A source's first preview is now queued and
  retried like run reports; later previews may still be dropped.

## Browser tests and screenshots

- **Playwright browser version.** If the headless shell pinned by
  `@playwright/test` is not installed but another build is, point
  `launchOptions.executablePath` at the installed one
  (`~/Library/Caches/ms-playwright/chromium_headless_shell-<build>/...`) in a
  scratch config instead of downloading. With no Playwright build at all, set
  `channel: "chrome"` to drive the installed Google Chrome, and `video: "off"` for
  the admin config, whose failure videos need Playwright's ffmpeg.
- **`vite preview` listens on `localhost` (::1).** E2E against it needs
  `STUDIO_BASE_URL=http://localhost:<port>`, not `127.0.0.1`.
- **`e2e/studio.spec.ts` needs a live API** at `STUDIO_API_URL` (default
  `127.0.0.1:8013`, started by `tooling/test-profile-studio.mjs`). Against
  `vite preview` alone it fails with "Failed to fetch". CI skips it, so it
  drifts: run `node tooling/test-profile-studio.mjs` after changing the studio.
  In a worktree, run `composer install` in `apps/api` first. A vendor copied from
  another checkout can lack a package, and every save then fails with a 500.
- **Mocked days are not 24 hours long.** A mock that steps `from + n * 86400000`
  across a daylight saving change lands an hour off the site's midnight, so a
  reading can fall into the previous day. The consumption test in
  `dashboards.spec.ts` failed every run for a week after Toronto's 2026-11-01
  change. Place mocked readings at noon, and compare zoned times with
  `Intl.DateTimeFormat`, never fixed UTC hours.
- **A hover straight from an open tooltip opens nothing.** Radix treats the pointer
  leaving an open tooltip's trigger as heading for that tooltip and ignores the next
  move on another trigger. Playwright's `hover()` sends one move and stays still, so
  the second tooltip never opens; it failed intermittently in CI after a click left
  the first tooltip open. Move away first (`page.mouse.move(0, 0, { steps: 5 })`) and
  expect no tooltip, as `gateway-firmware.spec.ts` and `onboarding-firmware.spec.ts` do.
- **Full-page screenshots break dashboards.** Playwright `fullPage` screenshots
  make react-grid-layout re-measure and collapse panels in the capture. Grow the
  viewport height instead.
- **Axe contrast failures whose colours change between runs** are samples taken
  mid-transition, not token bugs. Wait for
  `document.getAnimations().length === 0` before running axe, as
  `devices.spec.ts` and `onboarding.spec.ts` do.
- **Clicks inside an unfolding collapsible can be lost silently.** Playwright
  scrolls the `overflow-hidden` content to bring the target into its clipped
  strip, then the growing height moves the target between mousedown and
  mouseup. Playwright checks only the first event's hit target, so it reports
  the click as done while `click` fires on a parent. Wait for
  `document.getAnimations().length === 0` before clicking.
- **A picker could close the next picker on a busy page.** Radix returns focus
  to a closed popover's trigger in a `setTimeout`, and the browser runs input
  before timers. When the next picker opened first, the late focus closed it
  (CI: "element was detached" on an option until the test timed out). The kit's
  `PopoverContent` now leaves focus where it is if it has moved on; the
  dashboards spec reproduces the race by delaying zero-delay timers.
- **An icon toolbar button opens its tooltip when focus comes back.** Closing a
  table's Filters, Group, Columns or Sort menu returns focus to its icon button,
  whose tooltip then opens, and axe's `region` rule flags the tooltip because it
  renders outside any landmark. CI hit this on the Devices list while local runs
  passed. After picking from a picker inside Filters, wait for its combobox (with
  `exact: true`) to regain focus before pressing Escape; an Escape sent while it
  is still closing lands on the closing layer and leaves Filters open. Then expect
  the icon button focused, press Escape once more and expect no tooltip before
  running axe. When hovering several icon buttons in turn, move the pointer away
  in steps (`page.mouse.move(0, 0, { steps: 4 })`), or Radix keeps the first
  tooltip open. `devices.spec.ts` does all three.
- **Phone emulation hides sideways scrolling from `window.innerWidth`.** With
  `isMobile` (Playwright's phone devices), the viewport widens to fit content that
  overflows, so `scrollWidth - innerWidth` stays 0. Compare
  `document.documentElement.scrollWidth` with its `clientWidth`.
- **`rtk npx` rewrites to an npm script.** `rtk npx vite build` becomes
  `npm run vite`. Use `rtk proxy npx vite …` and `rtk proxy npx playwright …`.
- **`playwright install --with-deps` in CI waits on an Ubuntu mirror.** GitHub's
  Ubuntu runner already has Chromium's libraries, so the flag only adds fonts
  through apt. That took 30 s on one run and 11 min 40 s on another, which
  pushed the docs job past its 20-minute limit. CI installs the headless shell
  without it.
- **A mocked spec that opens the workspace panel must mock `/help/page`.** Catch-all
  mocks answer `{ data: [] }`, and the panel reads `articles[0]` from the page
  object, so the whole page falls to its error screen. The adapters spec mocks it
  next to the assistant routes.

## Assistant

- **Models mistype UUIDs and number types.** A tool argument can carry a UUID with one
  character changed, `"1"` for `1`, or leave a field out. Compare exact values only after
  normalizing, and make every refusal say which field is wrong and what it held; a vague
  "invalid binding" makes the model give up. Refused automation tool calls are logged
  as "Automation assistant tool refused".
- **OpenAI can send one reply twice.** A Responses stream can hold two output messages
  with the same text in one step, and the SDK's combined `text` joins them with no
  separator. `RunAssistant` builds the reply with `AssistantReply`, one paragraph per
  provider message, and leaves out a message that repeats an earlier one.
- **Show models the shape, not just the field names.** Given only field descriptions,
  models sent a parameter's `ingress_conversion` as a list three times and gave up.
  An example object in `ProfileKnowledge` fixed it.
- **Adapter readings skip a profile's ingress conversion.** Activation maps adapter
  devices with `conversion_mode: none`, so a profile's `ingress_conversion` does nothing
  for them and the decoder must return the profile's units. A WM-300 profile drafted with
  an mL→L conversion stored 12,000 L/min from a decoder that passed mL through.
- **Evidence pointers name items by their key.** The assistant writes a proposal's
  evidence as free-form pointers such as `parameters.temp.unit`, so renaming the key in
  review left every source for that item pointing at nothing, and the review kept
  saying you approved `temp`. `editedEvidence` now replaces an edited value's sources and
  rewrites the rest as `changes.N.values.<field>`. `evidenceTargets` also pairs old
  pointers with the one item nothing else names, which covers proposals saved before
  that change.

## UI

- **Navigating right after a successful save can hit the unsaved-changes guard.**
  `useUnsaved` clears the dirty flag in an effect, so `navigate()` in the same
  handler that marks the form saved still sees it dirty and shows "Leave without
  saving?". Store the result in state and navigate from an effect declared after
  `useUnsaved`, as `support/NewTicketPage.tsx` does.
- **`cn()` must know every named type size.** Plain `tailwind-merge` reads
  unknown `text-*` names as colours, so it used to turn
  `cn("text-meta text-muted-foreground")` into `text-muted-foreground` and drop
  `text-micro` from a `Badge`. The kit's `cn` now lists the scale in
  `packages/ui/src/lib/utils.ts`; when you add a `--text-*` size to
  `globals.css`, add its name there too. A named size also removes a `leading-*`
  class that comes before it in the same `cn` call, as `text-sm` does.
- **Toasts sit bottom-right and pause under the pointer.** A sticky bottom
  action bar needs `ref={keepToastsAbove}`, and a panel docked to the right edge
  needs `keepToastsLeftOf`, both from `@iot-os/ui/components/sonner`, or toasts
  will cover their buttons.
- **A `CollectionPage` description shares the title's row.** `PageHeader` shows it
  inline and truncates it, and the title truncates with it, so a sentence beside
  header actions cut the portal's title to "Billing acc…". Keep the description to
  a few words, such as a count ("4 of 4 organizations"), and put an explanation in
  a line above the table, as `billing/BillingAccountsPage.tsx` does.
- **A `DataTable` phone card is one big link.** The title's `RowLink` stretches
  over the whole card, so a button or switch rendered in a card's cell gets the
  link's tap instead. Give it `relative z-10`, as `RefLink`, the card's checkbox
  and its ⋯ menu have.
- **A wrapping `TabsList` overlaps what follows it.** Triggers are
  `h-[calc(100%-1px)]` of the list, so once `flex-wrap` adds a row each trigger
  grows with the list and the second row spills over the next element. Use
  `flex-wrap *:h-auto group-data-[orientation=horizontal]/tabs:h-auto`, as the
  device adapter wizard does.
- **A Radix `Select` keeps its old label when its options change.** Changing the
  value and the item list in the same render (for example switching provider and
  model together) leaves the trigger showing the placeholder. Give the `Select` a
  `key` tied to the option list so it remounts.
- **`fetchQuery` can return data that predates your write.** The portal's
  `QueryClient` sets a 15 s default `staleTime`, so `queryClient.fetchQuery()`
  after a mutation returns any copy fetched in the last 15 s, and joins a fetch
  already in flight, without refetching. A chat that polls only while a run is
  active then never shows the new run. Call `invalidateQueries` for that key
  first, or pass `staleTime: 0`.
- **Dashboard threshold bands run upward from their value.** A source's `base`
  band covers everything below its first threshold, and each threshold starts a
  band that lasts until the next one. A "low battery" warning is therefore the
  `base` band with a threshold at 20 labelled OK. A threshold at 20 labelled Low
  marks everything above 20 as low.
- **Don't switch an ECharts gauge's `progress` off and on.** ECharts 6 records
  the arc only while `progress.show` is true, and the next update reads that
  record, so a gauge drawn first without progress throws `Cannot read properties
  of undefined (reading '0')` (in `GaugeView._renderPointer`, which names the
  needle, not the axis pointer) when progress turns on. `gaugeOption` keeps it on
  and makes the arc transparent while there is no reading.
- **A chart inside an `aspect-ratio` box holds the box open.** ECharts sizes
  its inner element in pixels, and a box sized by `aspect-ratio` grows to fit
  its content. When the box narrows, the chart's last size keeps the height,
  the chart then measures the box at that height, and the arc is clipped. The
  gauge draws its chart in an `absolute inset-0` layer, so only the box's width
  and shape set its height.
- **`setSearchParams(updater)` starts from the last rendered address.** React
  Router hands the updater the search params from the last render, which can lag
  the address bar. On a slow machine, clearing a table's search and then picking
  a filter put the old search back (CI's admin users test failed this way).
  Change table state through `useUrlState` from `@iot-os/ui/hooks/use-url-state`,
  which starts each change from the address bar. In a browser test, wait for a
  search box to show what you typed before clearing it: until that render the
  controlled box still reads "", so filling "" changes nothing.
- **A tooltip on a disabled button never opens.** The kit's `Button` has
  `disabled:pointer-events-none`, so hovering it reaches no trigger. An icon-only
  button needs its name on hover, so `ToolbarButton` (from `data-table`) wraps a
  disabled button in a span that opens the tooltip; do the same for any other
  icon button that can be disabled.
- **Re-picking a parameter never refreshed an automation binding.** Deploy
  fails with `binding_changed: <role>` when any binding in the draft, used or
  not, names a device generation or configuration other than the current one.
  `SearchableSelect` skips `onChange` for an unchanged value, so picking the
  same parameter again did nothing. Picking another one added a binding under
  the node ID and left the old role behind. The editor now compares bindings with
  `generation` and `configuration_uuid` from `/dag/resources`, offers "Use
  current configuration" and drops unused bindings on save, so `/dag/resources`
  must return the generation that deploy checks.

## Docs site

- **Astro runs one preview server per project.** A second `astro preview` (for
  example Playwright's `webServer`) exits at once. `apps/docs` tests reuse the

- **Starlight's `docsLoader` takes no pattern.** To leave a folder out of the

  `apps/docs/src/content.config.ts` does for gated features.
- **starlight-openapi ignores `x-` extensions and external `$ref`s.** The sources

- **An empty Actions secret reads as an empty string, not unset.** Scripts that

- **Help guides never name the product.** The release checks that a build with

## Embedded SDK

- **coreMQTT 2.3.1 reports an idle socket as success.** `MQTT_ProcessLoop` turns
  `MQTTNoDataAvailable` into `MQTTSuccess`, so looping until it stops succeeding spins
  until the deadline (forever on a frozen test clock). `mqtt_stream.c` stops once a pass
  received no bytes and nothing is buffered.
- **coreMQTT's time function takes no context.** `MQTTGetCurrentTimeFunc_t` is
  `uint32_t (*)(void)`, so the SDK cannot reach its gateway from it without static
  data. The clock port carries a context-free `monotonic_ms` for this, and the SDK uses
  it for every interval.
- **Bare-metal ARM enums are short.** `arm-none-eabi-gcc` defaults to `-fshort-enums`,
  so an enum value can be one unsigned byte: `(int)type < 0` is always false and fails
  `-Werror=type-limits`. Range-check enums as unsigned. The arm `iotos_size` build in CI
  catches this; the desktop compilers do not.
- **The SDK matches device types by address.** A type header (`iotos_type_<id>.h`) defines
  `static const` tables, so every file that includes it gets its own copy. Registering
  `iotos_kit_types[i]` and then adding a device with another file's `&iotos_type_x` gives
  `IOTOS_E_INVALID`. Starters keep the headers inside `generated/iotos_types.c` and
  expose only `iotos_kit_types[]` and `iotos_kit_node_type`.
- **A starter's settings are picked up at configure time.** `iotos_starter.cmake` checks
  for `config/iotos_settings.c` when CMake configures. It adds `config/` to
  `CMAKE_CONFIGURE_DEPENDS`, so unpacking the settings re-runs the configuration on the
  next build; a folder created later than the first configure does not.
- **esp-tls leaves its connect timeout on the socket.** `esp_tls_conn_new_sync` sets
  `SO_RCVTIMEO` to the config's `timeout_ms`, so every later read blocks that long
  (10 s) and `iotos_poll` stalls. The ESP-IDF stream port sets 20 ms after the
  handshake. ESP-IDF's mbedTLS socket layer counts `EAGAIN` as "want read" even on a
  blocking socket, so the expiry reaches the SDK as "nothing yet".
- **`iotos_poll` returns at once while it waits to reconnect.** A FreeRTOS loop that
  only calls it then never blocks, and the idle task starves (the task watchdog
  complains). The ESP32 example waits one tick per pass; the Linux one spins during
  back-off.
- **ESP-IDF reads every component's CMakeLists.txt twice.** The first pass runs it in
  script mode to collect requirements, where `idf_component_register` is a macro that
  ends with `return()`. Code after it runs only in the real pass, and commands before it
  must work in script mode (`set`, `include`, `get_filename_component`, `if(EXISTS)`).
  `ports/esp-idf/component.cmake` keeps `target_*` calls after the registration.
- **A starter's ESP-IDF component file is kept on update.** `components/iotos/CMakeLists.txt`
  is a project file, not a replaceable one, so it only locates the folders and includes
  `sdk/ports/esp-idf/component.cmake`. A source list written there would miss files a
  later SDK adds.
- **ZIP times have no time zone.** Phar writes each entry's DOS time as the server's
  UTC wall clock, and unzip tools read it as local time, so a starter unpacked west of
  UTC held files hours in the future. CMake then sees its inputs newer than the build
  and regenerates forever (`build.ninja still dirty after 100 tries` with `idf.py`).
  `FirmwareArchive` stamps every entry a day back, which is in the past in every zone.
- **Download endpoints share one throttle per person.** `throttle:10,1` keys on the user,
  not the route, so onboarding provisioning, connection kits, firmware starters,
  settings and kits all count against the same ten a minute. Feature tests that download
  many archives turn off `ThrottleRequests`; `StarterTest` checks the limit once.
- **MCUXpresso SDK 26.x has no `armgcc/build_*.sh` scripts.** Projects are
  "freestanding": a `CMakeLists.txt` that includes `cmake/extension/mcux.cmake` before
  `project()` and the SDK's `CMakeLists.txt` after it, a `prj.conf` merged after the
  device's, board's and examples' own, and the board files copied into the project. The
  build type (`flexspi_nor_sdram_debug`) picks the linker script, and the board's CMake
  adds the DCD and `SKIP_SYSCLK_INIT` for it. Kconfig rejects a number for a bool
  (`configCHECK_FOR_STACK_OVERFLOW=y`, not `2`).
- **The MCUXpresso ENET port passes `-DCHECKSUM_GEN_IP=1` and friends.** An `lwipopts.h`
  that also defines the `CHECKSUM_*` options fails with redefinitions under `-Werror`.
  lwIP's SNTP hook (`SNTP_SET_SYSTEM_TIME_US`) is a function-like macro, which the
  generated lwIP configuration cannot express, so the RT1050 example sets
  `middleware.lwip.generated_config=n` and keeps its own `lwipopts.h`; that file needs
  `LWIP_DEFINE_LWIP_RAND_IN_CC_H 1` for `LWIP_RAND`.
- **The RT1050 has no MCUXpresso mbedTLS entropy port.** `port.rng` is not offered for
  it, and NXP's RT1050 examples take entropy from a PSA driver in another repository.
  The IoT OS port builds mbedTLS without PSA and reads the TRNG in
  `mbedtls_hardware_poll` (`MBEDTLS_ENTROPY_HARDWARE_ALT`).
- **After a rebirth, a paced gateway's devices have no birth for up to 25 s.** The
  runtime's Sparkplug engine forgets a node's devices on its NBIRTH, and the SDK
  re-announces them at 20 per second. Activations in that gap were refused as offline
  (up to 245 of 247 in a bulk onboarding), commands to its devices too, and each
  activation that did apply asked for another rebirth, which opened the gap again. The
  Python simulator re-announces at once, so checks against it never saw this. The
  runtime now holds such an activation until the device's birth, for up to 90 s, and
  one whose device's birth is live hands that state on instead of asking for a rebirth
  (spec 026 research R19). Test bulk paths against the SDK simulator, not only the
  Python one.
- **pymodbus data blocks are 1-based.** `ModbusSequentialDataBlock.getValues` receives
  the register number plus one, so a block that starts at 0 answers every read one
  register late. `tooling/hardware/modbus_simulator.py` starts its block at 1.
